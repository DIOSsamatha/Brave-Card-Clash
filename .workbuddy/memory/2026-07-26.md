### `SkillResult` 内部类类型注解解析失败 (`game_state.gd:148`)
- **原因**: `SkillResult` 定义为 `SkillExecutor` 文件内的内部类，同时加了 `class_name SkillResult` —— GDScript 2.0 **不支持同一文件两个 `class_name`**
- **修复**: 
  - 新建 `scripts/resources/skill_result.gd` 独立文件，`class_name SkillResult extends RefCounted`
  - 从 `skill_executor.gd` 移除内部类定义
  - `game_state.gd:148` 的 `result: SkillResult` 类型注解现在能正确解析
- **教训**: GDScript 2.0 中需要跨文件引用的类型，必须放独立文件 + 独立 `class_name`，不要用内部类

### GDScript 2.0 全局函数返回类型修复
- Godot 4中以下全局函数返回`Variant`，不能直接用`:=`推断类型
- 必须用类型化版本:
  - `min(a, b)` → `minf(a, b)` (float) / `mini(a, b)` (int)
  - `max(a, b)` → `maxf(a, b)` (float) / `maxi(a, b)` (int)
  - `abs(x)` → `absf(x)` (float) / `absi(x)` (int)
  - `clamp(x, min, max)` → `clampf/clampi`
  - `lerp(a, b, t)` → `lerpf()`
- 修复位置:
  - `game_state.gd:102` `min(player_shield, remaining)` → `minf(...)`
  - `game_state.gd:116` `min(enemy_shield, remaining)` → `minf(...)`
  - `game_state.gd:127` `min(player_max_health, ...)` → `minf(...)`
  - `roguelike_map.gd:202` `min(3, current.size())` → `mini(...)`
  - `battle_manager.gd:233` `abs(p_val - d_val)` → `absi(...)`

### Object 内置方法命名冲突修复（关键崩溃Bug）
- **根因**：`StanceData.get_name(stance)` 与 Godot `Object.get_name()` 内置方法重名
  - `Object.get_name()` 是无参内置方法，我们定义的 `get_name(stance)` 有参数
  - 调用时 GDScript 解析器报 `Invalid call to function 'get_name'. Expected 0 argument(s)`
  - 这导致 `_select_stance()` 崩溃 → 选择姿态后整个战斗流程卡死
- **修复**：
  - `stance_data.gd`: `get_name()` → `get_stance_name()`
  - `battle_scene.gd:93`: 调用点同步更新
- **经验**：Godot 4 中绝对不要用以下名字定义自定义函数：
  - `get_name`, `get_path`, `to_string`, `_init`, `_notification`
  - 以及所有 `Object` / `Node` 的内置虚方法名
- **额外修复**：5个信号回调中未使用参数加 `_` 前缀消除警告
  - `_on_health_changed(_target, _new_health, _max_health)`
  - `_on_hand_changed(_cards)`
  - `_on_round_result(result_text, _damage)`
  - `_on_round_started(_round_number)`
