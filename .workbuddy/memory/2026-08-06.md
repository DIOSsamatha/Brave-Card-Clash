## 修复存档反序列化 Array 类型错误
- 文件: scripts/core/save_system.gd
- 问题: 读档时报错 `Invalid assignment of property or key 'unlocked_trumps' with value of type 'Array' on a base object of type 'RefCounted' (SaveData)`。
- 根因: SaveData.unlocked_trumps/unlocked_items 声明为 Array[String]，但 JSON 解析返回的是无类型 Array，直接赋值触发类型错误。
- 修复尝试 1: 对 JSON 读出的 Array 显式 `as Array[String]` 转换，但 Godot 中该转换对无类型 Array 不生效。
- 修复尝试 2: 改为使用 typed_array.assign(raw_array)，让 `Array[String]` 自动复制并校验元素类型。

## 修复地图节点不可达 bug
- 文件: scenes/map/map_scene.gd
- 问题: 玩家选择某节点后，下游/同层部分节点变得不可点击。根因是地图生成时连接算法为随机 shuffle，不保证下一行每个节点都有来自前一行的入边，导致某些节点从任何已访问节点都不可达。
- 修复: 重写 `_generate_new_map` 中连接上一行到下一行的逻辑：
  1. 保证下一行每个节点至少有一个来自前一行的入边；
  2. 保证前一行每个节点至少有一个指向下一行的出边；
  3. 再随机添加少量交叉连接保留分支路线图感。
- 状态: 第一次修改后用户反馈仍不行（下一行同列/同层节点被锁死）。
- 第二次修复: 将每行节点数固定为 MIN_NODES_PER_LAYER(3)，并让每个前驱节点全连接到下一行所有节点。这样从任意已访问节点出发，下一行全部节点都可达。再次等待实测验证。
- 第三次修复: 用户反馈路线不要全连接，要随机且按路线给可去节点。新增 `_connect_rows` 函数：1) 下一行每个节点优先从同列获得入边；2) 上一行每个节点至少两个出边（正对+随机）；3) 少量随机额外交叉连接。既保证从任意已访问节点出发都有 2~3 个选择，又保留随机分支感。再次等待实测验证。
- 第四次修复: 用户反馈仍太像网格、连线太密。重写 `_connect_rows`：1) 每个前驱节点只连正对列，50% 概率再连一个相邻列；2) 保证每个下游节点至少 1 条入边；3) 最多 1 条远距离交叉线。大幅降低连线密度，形成真正的随机分支路线。
- 第六次修复: 用户反馈"点过第一行事件节点后，红圈节点不应可访问"，即路线应真正分支。重写 `_connect_rows`：1) 每个前驱节点只连 1 个下游节点，形成清晰路线；2) 只允许连到同列或相邻列，路线自然蜿蜒；3) 保证每个下游节点至少 1 条入边。起点仍连到第一行全部 4 个节点供玩家选择。选择某节点后只能沿该路线前进，未被选中的分支不可达。

## 再次修复底部立绘不显示
- 文件: scenes/battle/battle_scene.tscn
- 问题: 用户反馈底部两侧仍然看不到角色和怪物立绘。
- 根因: 当 anchor_top = anchor_bottom = 1.0 时，offset 是相对于屏幕底边的有向偏移；y 轴向下为正，因此 offset_top/bottom 必须为负值才能让矩形位于屏幕底部以内。此前改为正值 300/20 导致矩形整体跑到屏幕底边下方，且 offset_top > offset_bottom 使高度为负，节点完全不渲染。
- 修复:
  - PlayerPortrait: anchors_preset=3（左下），offset_top=-300，offset_bottom=0，宽度 300，紧贴底边上方。
  - EnemyPortrait: anchors_preset=4（右下），offset_top=-300，offset_bottom=0，宽度 300，紧贴底边上方。
  - 显式设置 anchor_left/right 避免预设与显式值不一致。
  - 两个立绘节点 z_index=5，确保显示在 BottomBar 之上而不被底部按钮栏遮挡。
  - 用户实测反馈位置偏低，将 offset_top 从 -300 调整为 -380，offset_bottom 从 0 调整为 -80，使两个立绘整体上移 80 像素。

- 问题: 调试器报错 `battle_scene.gd:346 @ _update_skill_tooltip_hover(): Parameter "get_viewport()" is null.`。
- 根因: `_process` 中每帧调用 `_update_skill_tooltip_hover`，切换场景或节点短暂不在场景树时，`get_global_mouse_position()` 会尝试获取 viewport 而失败。
