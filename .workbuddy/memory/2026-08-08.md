## 修复「显示已造成伤害但不扣血」bug

### 根因
- `battle_manager.gd` 的 `_resolve_round()` 中，结算文字 `"你赢了！造成 %.1f 点伤害！"` 用的是 `_calculate_damage()` 返回的**原始 damage**，但实际扣血走 `_deal_enemy_damage(damage)`；该函数内部会被敌方减伤机制把 `dmg` 减到 0。
- 用户此前把角色基础伤害砍到 3.5~4.0，而第1层精英「古树守卫」有「单次减伤5点」机制（5.0），低伤害直接被全吞 → 文字显示"造成4点"，实际扣0点，表现为"打不出伤害"。
- 显示与实际扣血量不一致是核心缺陷（UI 刷新链路 health_changed → _on_health_changed → _update_hp_display 本身正常，非 UI 问题）。

### 修复内容
- `_deal_enemy_damage` / `_deal_player_damage` 改为返回 **实际造成/受到的伤害 (float)**。
- `_resolve_round` 的结算文字改用函数返回值（真实扣血），emit 的 damage 仍保留原始值用于胜负动画方向。
- 在扣血函数内加兜底：`amount > 0` 且减伤后 `dmg <= 0` 时强制 `dmg = 1.0`，保证"减伤"而非"免伤"。
- `enemy_mechanics.gd` 中古树守卫 `ENEMY_ONCE_REDUCE` 值由 5.0 降为 2.0（当前低伤害环境下更合理，不会吞光所有伤害）。

### 改动文件
- `scripts/core/battle_manager.gd`（_deal_enemy_damage / _deal_player_damage / _resolve_round）
- `scripts/core/enemy_mechanics.gd`（ancient_guard 减伤 5→2）

## 每层怪物随机池修正（2026-08-08 19:35）

- 问题：用户反馈每层战斗/精英节点的怪像「固定顺序」。根因：普通战斗节点（MONSTER）调用 `get_random_enemy_for_layer(layer_idx)`，而该函数内部只筛 `EnemyType.NORMAL`，导致第1层普通战斗永远只在嫩芽妖精/荆棘藤蔓/恶作剧花精这3个普通怪里随机，永远遇不到古树守卫、幻光独角仙两个精英怪。
- 修复：
  - `scripts/resources/enemy_database.gd`：新增 `get_random_any_for_layer(layer_idx)`——从本层「普通+精英」全部怪物池随机选取（`RandomNumberGenerator.randomize()` 保证真随机）。
  - `scenes/map/map_scene.gd`：普通战斗节点（298行附近）由 `get_random_enemy_for_layer` 改为 `get_random_any_for_layer`，现在普通战斗也会随机遇到本层精英怪；精英节点仍用 `get_random_elite_for_layer`（从精英池随机，保持精英强度区分）。

### 改动文件
- `scripts/resources/enemy_database.gd`
- `scenes/map/map_scene.gd`

### 设计决策
- 普通战斗从「本层全部怪物」随机（含精英），精英节点从「本层精英」随机。若用户希望精英节点也从全部怪物（含普通怪）随机，可再调整。
- 地图生成时敌人即定死（roguelike 标准行为，地图种子固定），同一节点在同一次冒险中敌人不变属正常。

## 修复地图生成缩进错误（2026-08-08 22:17）

- 问题：上一条修改 `scenes/map/map_scene.gd` 时破坏了 `for i in range(MAX_NODES_PER_LAYER):` 循环体的缩进，导致 `# 根据当前层分配敌人数据` 到 `id_counter += 1` 被解析到循环体外，Godot 编辑器报错：`Identifier "ntype" not declared in the current scope`、`Identifier "node" not declared in the current scope`。
- 修复：
  - 将 `if ntype == NodeType.MONSTER:`、`elif ntype == NodeType.ELITE:`、`_map_nodes.append(node)`、`new_row_nodes.append(node)`、`id_counter += 1` 整体缩进一层，放回 `for i in range(MAX_NODES_PER_LAYER):` 循环体内部。
  - 同时修正 `_map_nodes.append(node)` 等三行原本误挂在 `elif` 分支下的问题，现在对所有节点（普通/精英）都会执行 append 与 id_counter 自增，避免普通战斗节点丢失。
